# T321 灰度连续帧接收修复（2026-10-25）

用户反馈按 USER 完全不动。原 T321 的板内状态为启动门控已中止、轨迹 0 条、电机 PWM 0；灰度有效帧 0，未识别字节持续增加，陀螺仪、编码器和使能正常。具体中止瞬间原因未单独记录，但当前灰度离线足以阻止启动。

保存现场后，主板复位及用户整车重新上电均未恢复通信。临时烧录既有无电机启动路径的 GrayLearn 采集程序，从真实串口捕获到连续的 `55 AA 02 10 ...` 模拟量帧，两个完整帧的校验和均正确。旧接收器要求先查询、再等待尾部静默；连续数据既被视为非请求回复，又不断推迟下一次查询，导致有效帧一直为零。传感器为何进入连续上报状态尚未确定。

修复 `Core/Src/gray_analog.c`：按帧头、命令、长度和校验和同步接收，兼容连续上报与查询回复；坏帧后寻找下一帧头，保留 UART 错误、20 ms 接收超时和 100 ms 数据过期检查。完整模拟量帧验证后才发布八路数据；正常连续流的发布间隔至少 12 ms，避免串口满速上报使按帧计算的路线修正频率骤增。无效后收到新有效帧可立即恢复。速度、标定值、路线算法及 USER 启动逻辑未修改。

验证：真实原始帧回放、每个字节损坏、所有初始字节偏移、连续无间隙报文、阈值帧排除、时间回绕、部分帧超时、过期与原查询模式测试通过；完整 T321 ASAN/UBSAN 回归退出码 0，共 1123 条 PASS。固件 BIN/HEX、向量和回读一致性检查通过。RAM 地址布局未变。

烧录后两次只读检查：灰度在线，有效帧 420 → 503；超时 0、错误 0；启动同步时丢弃 9 字节，后续未增加。其余就绪标志均正常、fault 0、PWM/CCR 全零、默认 NORMAL / 1 圈。未远程启动，实际按键启动和赛道运行仍待用户验证；此前四圈可靠性问题不能据此宣称解决。

本版标记为 **T321-UART**，保留 T321 RAM 魔数，不可只凭魔数区分旧版；BIN 大小 51364 B，SHA256 为 `1db5a190315810ef895830e855464aa82a4aa055637f5ade740200e03a89ebdc`。原 `firmware/T321/` 发布包未覆盖，修复镜像归档于 `.tools/hardware-backups/t321-uart-validated.*`，当前构建在 `build-local/ArcPhaseDebug/`。本次未上传 GitHub。
