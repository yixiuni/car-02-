# H题实现与实车标定

本固件以 C10B 加两台 MG513X 电机完成 H 题路线的课程复现。用户已确认轮胎直径为 65 mm；具体减速比、编码器计数和安装尺寸需要实测。下面的步骤使源码中的毫米、速度和航向对应到真实小车。

## 先填写参数

在 `Core/Inc/car_config.h` 填写以下数值，测量结束前保持 `CAR_CALIBRATION_CONFIRMED=0`。

| 参数 | 含义 | 当前值 |
| --- | --- | --- |
| `CAR_WHEEL_DIAMETER_MM` | 有效滚动直径 | 65 mm，来自用户；负载后可进一步修正 |
| `CAR_ENCODER_A_COUNTS_REV` | A 轮转一圈的 TIM4 x4 总计数 | 0，待测 |
| `CAR_ENCODER_B_COUNTS_REV` | B 轮转一圈的 TIM8 x4 总计数 | 0，待测 |
| `CAR_WHEEL_TRACK_MM` | 左右轮接地点中心之间的距离 | 0，待测 |
| `CAR_FRONT_MM` / `CAR_REAR_MM` | 轮轴中点到车体最前／最后的距离，包含传感器 | 0，待测 |
| `CAR_HALF_WIDTH_MM` | 以轮轴中点为基准的车体最大半宽 | 0，待测 |
| `CAR_SENSOR_FORWARD_MM` | 轮轴中点到灰度探头横排的前向距离 | 0，待测 |
| `CAR_GRAY_PITCH_MM` | 相邻探头中心间距 | 12 mm 为初始估计，需测量 |

MG513X 型号不能唯一确定每轮计数。计数换算为 `编码器每电机轴一圈脉冲数 × 减速比 × 4` 时，须确认厂家给的脉冲数是否已经倍频；不可重复乘 4。最直接的方法是使能关闭、手动转输出轮整整 10 圈，读取 `app_diagnostics.encoder_a_counts` / `encoder_b_counts` 的增量，再除以 10。该诊断在未完成尺寸标定时也有效。

两轮距离分别为 `计数 × π × 有效轮径 / 每轮一圈计数`。标定计数后，推车沿已量好的 1 m 直线检查距离。若计算距离为 d，且确认无滑动，可将有效轮径更新为 `原轮径 × 1000 / d`。测试场地上的量尺只用于调试，正式运行时不添加赛道标记。

配置校验要求车体前后总长不超过 250 mm、半宽不超过 75 mm。若实车尺寸不同，应明确课程验收是否仍执行原题尺寸要求，再调整尺寸限制；不能为了通过检查填写虚假尺寸。

## 检查传感器和方向

1. 灰度模块与主板共地，供电正确，TX 接 PC11、RX 接 PC10。整套断电重启，黑线学习为目标、白底为背景；使用与学习时相同的探头高度。`gray_samples` 应持续增加，`gray_online` 应为真。
2. 从车左到右遮挡八路探头，`black_mask` 应依次为 `0x01` 至 `0x80`。若顺序相反改 `CAR_GRAY_REVERSE_ORDER`；若极性相反改 `CAR_GRAY_TARGET_BIT_IS_ONE`。当前协议为上电 `0x00` 手动模式、`0x01` 单字节状态查询。
3. 手动向前转两轮，相应编码器计数应增加。反向则修改 `CAR_ENCODER_A_SIGN` / `CAR_ENCODER_B_SIGN`。确认 A/CN3 是否在左边，必要时修改 `CAR_LEFT_IS_MOTOR_A`。
4. MPU6050 平放，Z 轴垂直地面；静止上电完成约 400 个采样的零偏校准。`mpu_online`、`imu_ready` 应为真。逆时针转动车头，`yaw_rad` 应增加；反向则修改 `CAR_GYRO_Z_SIGN`。绕其他轴安装需要修改采样轴，当前仅支持 Z 轴偏航。
5. 实车参数及方向确认后启用校准开关，先架空进行极短启动、使能停车检查。若电机正转方向错误，调整相应 `CAR_MOTOR_*_FORWARD_IN1`。架空状态缺少地面航向响应，不用于路线验收。
6. 检查蜂鸣器极性和 LED 提示。故障灯也用于表示标定、灰度或 IMU 尚未就绪。

IMU 在任何采样失败或过长间隔后丢弃旧航向，停车状态下重新校准；不得用手转动小车完成零偏校准。MPU6050 的加速度不能提供绝对偏航，本方案利用静止零偏、灰度循迹及合格弧线端点约束长期误差。

## 放车和按键

每次开始将轮轴中点放在 A。任务 1/2 朝向 B；任务 3/4 朝向 C，即相对 AB 向右下 38.66°。程序把这一摆放方向视为初始已知航向，不能任意朝向启动。

停车时长按 USER 0.8 秒切换任务，提示次数表示编号；短按并松开启动。行驶中按下 USER 停车，松开不会再次启动。使能关闭、传感器故障或完成后的恢复都需要重新摆车、重新短按。上电时按住 USER 不启动。

## 分段控制

地图以 A 为 `(0,0)`，B 为 `(1000,0)`，C 为 `(1000,-800)`，D 为 `(0,-800)`，单位毫米，逆时针角度为正。

直线段根据编码器里程和陀螺仪积分更新轮轴中点位置，同时控制目标航向和横向偏差。预期端点附近降低速度，用连续三帧黑线及位置、投影覆盖条件确认入弧。弧线中途全白触发短暂曲率预测，持续 180 ms 则停车；白底直线不会触发此故障。

斜线到半圆的夹角约 38.66°。`CAPTURE` 状态低速向前转至半圆起点切线方向，连续黑线稳定后进入 `ARC`。没有原地反转或倒车指令。任务 3 的右半圆 C→B 为逆时针，左半圆 D→A 为顺时针；任务 2 两段均顺时针。

灰度位置以八路加权均值计算；新帧才更新微分。半圆使用 `ω = ±v/400 - Kp×灰度偏差 - Kd×偏差变化率`，再按轮距换算两轮目标速度。内层为带积分限幅的 PI 和速度前馈，PWM 限于 0～700‰。增益是初始调试值，不是 MG513X 的实测辨识结果。

弧线离开判据同时检查行程、转角、端点位置、航向、最后黑线是否居中和连续白底。此时前置探头在端点附近，轮轴还在后方，不能把车身航向直接设置为端点切线角。程序使用 `切线角 − 弯向×asin(探头前置距离/400)` 估算车身航向，并以 0.5 比例、有界修正。该几何关系假设末段稳定沿圆弧运动；过渡振荡、探头高度变化或较大轮胎滑动会破坏假设，必须实车观察调节。

最终过点后切断驱动并观察轮速，连续 120 ms 低于 10 mm/s 且估计车体覆盖目标点，才进入完成状态并提示。停车仍是滑行；程序没有把双输入低当作主动制动。

## 按顺序调试

1. 先完成 1 m 直行，记录计算距离、实际距离和横向偏差。轮速 PI 在不同电池电量下应能维持目标速度。
2. 完成任务 1，重复至少 5 次，记录停止投影是否覆盖 B；再调整接近速度和停车策略。
3. 单独检查两种弯向的半圆，观察 `black_mask`、`line_error_mm`以及弧线末端的真实车头角度。灰度左右顺序或陀螺仪符号错误应先修正，不能靠改 PID 正负抵消。
4. 完成任务 2，确认 B、C、D、A 每点提示一次，30 秒内完成。
5. 完成任务 3 两处斜线接弧，检查是否覆盖 C、D，且弧线运动期间车体投影没有完全离开黑线。
6. 完成四圈，记录每圈用时、过点次数和终点偏差。稳定后逐步提速，每次仅调整一组参数。

任务 4 使用 160 秒软件保护超时。它是开发时的故障保护设置，不是原题规定的时间上限。任务 1～3 分别采用 15、30、40 秒限时。

## 诊断故障

| `fault` | 含义及排查 |
| --- | --- |
| 0 `CAR_OK` | 无锁定故障；仍需检查各 ready 字段 |
| 1 `CONFIG` | 必填尺寸、计数或确认开关未通过 |
| 2 `GRAY` | UART 超时、错误或陈旧数据 |
| 3 `IMU` | 校准未完成、采样失效或异常角度跳变 |
| 4 `ENCODER` | 数据无效、方向错误或不可能的里程跳变 |
| 5 `TIMING` | 控制间隔超过 50 ms |
| 6 `STALL` | 一轮被要求前进，却持续无有效速度 |
| 7 `LINE` | 入弧失败、持续丢线或弧线进度异常 |
| 8 `ENDPOINT` | 错过端点，或最终停车未覆盖目标 |
| 9 `TIMEOUT` | 整项任务超时 |

模拟模型不能代替真实串口、编码器电平、地面摩擦、传感器高度和轮胎滑移测试。尤其要用实车验证端点探头偏移、弧线末端航向修正与停车滑行距离。

## 设计报告材料

报告可按系统框图、硬件接口、轮速与航向控制、灰度算法、状态流程、误差来源、测试结果编写。测试表应记录任务编号、重复次数、用时、终点偏差、过点提示是否完整、弧线是否脱离，以及电池电压和地面条件。软件模拟结果只能标为模拟，不填入实车成绩栏。
