- 首圈两段直线，在规划中心速度约 800 mm/s 的区间，时间加权实速分别约 836/819 mm/s，PWM 均值约 818/792。测量包含原 30 ms 滤波滞后；它不支持“巡航一直追不上目标”的判断，暂不据此添加加速度前馈。

## 使用

长按 USER 约 1 秒切到 CROSS，确认 LAPS 4。驱动轮轴线中点放在 A，车头朝 B，前排探头白底。拔电脑线后短按 USER，由原程序静止校准后启动。跑完保留电池供电，接回电脑，勿复位或再次启动，以保留 RAM 记录。

## 记录内容

新增 `speed_trace.c`，在本轮电机输出提交后观察只读控制数据。第一圈 segment0 与 segment2 各保存一个直线窗口，最短间隔 20 ms（实际随控制周期对齐），每窗口 104 条、每条 28 B，约 5.7 KiB。记录：时间、规划左右轮目标、限加速度后的左右设定值、滤波实速、PI 积分贡献、PWM、状态/段号/事件数。速度单位 mm/s，积分/PWM 单位千分比，浮点量四舍五入至整数。

每窗口保留起点与离开直线的终点；容量不足会计数并保留最后终点，不能把发生截断的窗口称为完整记录。完成后冻结，不被后续圈或待机覆盖；新一次物理按键启动的校准阶段清空计数。没有串口实时上传，也没有远程启动入口。

记录中的实速来自原编码器 30 ms 低通滤波器，本行 PWM 在该行测量之后提交。后续识别必须考虑这一先后关系和滤波延迟，不能用同一行 PWM/实速直接拟合瞬时电机模型。`decode_speed_trace.py` 只计算目标斜坡差、跟随误差、峰值等诊断，不自动生成 Ka。
