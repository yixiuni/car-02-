# T320 出弯观测时刻补偿与接线调整

2026-10-25。最新实跑失败：第二圈 B 点 11.872 秒，不能作为稳定版本。

## 依据

T319 两次留存成功记录为 29.975 / 29.730 s；随后用户报告约五六次均失败，位置涉及 A、C、D。最近一次 RAM 确认首圈 A 在 7.791 s 失败：第一个出弯候选校正量 110.78 mm，超过 100 mm，之后继续前进导致失线停车。C/D 暂无失败现场，不能推断全部失败同源。[失败证据](data/t319-cross-four-run-03.json)。

代码中的出弯观测来自连续白色确认，但旧算法把确认时刻的车身姿态直接用于黑线末端定位，没有传播黑白边沿到确认之间的运动。T319 的径向位置约束也不能独立消除沿弧方向的误差。

## 修改

- 仅 CROSS 保存最近的有效居中黑线姿态。在首次白色到来时，以相邻黑/白观测姿态的中点近似边沿时刻，再冻结该姿态。要求窄而连续的 1～3 探头、至少三帧黑色、中心 ±22.5 mm、黑白观测间隔不超过 40 ms。旧帧、全黑、分裂图案不能建立边沿。
- 三帧白色确认时，依据编码器/陀螺仪积累的位置和角度变化，把边沿位置观测传播到当前时刻。航向观测采用边沿时刻，应用原有的小幅融合；相对位移随该融合旋转。
- 保留 100 mm 校正上限、原有行程/转角/时效/距离/车体覆盖条件与失线截止。缺失有效边沿姿态也不能出弯，诊断拒绝位新增 1024。
- C/D 瞄准位置由沿半圆前进 30/35 mm 调整为 15/15 mm，减少新定位下过早切入半圆。三帧黑色、点位置与覆盖门限保持。
- CROSS 直线/弯道/接线目标仍为 1000/650/370 mm/s；NORMAL 保持原控制与 1/4 圈选择。加密端点附近的 RAM 轨迹采样，便于后续区分 C/D 接线失败原因；不增加自动启动。

黑白边沿中点只是有限采样下的近似，尚未实测探头处理延迟。以上修正是有模型支持的候选，不是对未留存的五六次失败的完整重放。

## 验证

- ASAN/UBSAN 回归退出码 0，1123 条 PASS。新增边沿中点、冻结、模糊/过时观测排除、运动传播不回跳、段切换清空、位置/航向/时效门限和停机测试。初次测试夹具把 now 与 last_update 设成同一时刻而未执行更新，已修正夹具；最终日志为 `.tools/hardware-backups/t320-tests-final.log`。
- 完整扩展模型 224/225；唯一失败仍是原有 NORMAL、系数 1.5、采样相位 14 的 D 点覆盖场景。CROSS 完整、C 偏移、D 偏移各 45/45。报告 `build-host/t320-final/report.json`。
- 90 组人工注入里程估算漂移：T319 73/90，T320 90/90；这只是受控模型，不是实车噪声拟合。[漂移记录](data/t320-drift-check-2026-10-25.json)。
- NORMAL 45 组控制指纹与归档 T317 一致。[等价记录](data/t320-normal-equivalence-2026-10-25.json)。
- 单独加入时刻补偿曾只有 197/225 通过；扩大覆盖内缩或进一步收紧探头条件也出现新失败。这些候选未烧录，失败报告保留在 `build-host/t320-edge-research/`。最终候选在原门限基础上将 C/D 瞄准距离设为 15 mm，并完成上述全量验证。

## 固件与读取

`build-local/EdgePoseDebug/stm32-car.*`，魔数 `0x54333230`，Flash 50460 B，链接 RAM 47304 B。镜像归档 `.tools/hardware-backups/t320-edge-pose-validated.*`。完整 SHA256 与部署状态见[验证记录](data/t320-validation-2026-10-25.json)。烧录前保存了 T319 失败 RAM 与 Flash，前缀 `t320-before-01`，备份 Flash 与原归档哈希一致。

CarControl 追加 16 B，变为 204 B；原 run_at 偏移 148 不变，后续全局地址移动。必须用 `tools/read_t320.tcl`，不能沿用 T319 的读取地址。电机只由物理 USER 启动。

试跑选择 CROSS / LAPS 4，驱动轮轴线中点对准 A、车头朝 B、前排探头在白底。拔电脑线，短按 USER 并松开。跑后保持电池供电、接回电脑、不复位；无论成功或失败都先回收数据，不能把一次通过当作稳定验收。

## 实跑失败：第二圈 B

用户确认 B 点。最新 RAM：第一圈 B、A 均一次通过，第二圈 C 已确认；第二圈 B 在 11.872 s 触发 fault7。第一次候选的边沿航向误差只有 0.00804 rad、最后黑线径向残差 −8.03 mm，但当前位置到 B 的距离以及端点校正量 121.24 mm 不满足门限。后续 26 次候选一直未通过，最后失线停车。三段弧线确认时的里程分别约 1146 / 1183 / 980 mm，说明现有沿弧位置估计仍不一致；这些内部数据不能单独证明打滑或唯一原因。
